# Lumen Duel

Браузерная дуэль на энергоклинках с физической боёвкой. Клинок следует за мышью, урон зависит от реальной скорости лезвия в момент касания, блоки и парирования возникают из столкновения клинков, а не из кнопки.

## Запуск

Сборка не нужна: это чистый HTML, CSS и JavaScript.

Локально достаточно открыть `index.html` двойным кликом. Если браузер что-то блокирует, подними простой сервер:

```bash
npx serve .
```

## Деплой на Vercel

1. Залей папку в репозиторий на GitHub.
2. В Vercel нажми Add New, затем Project, выбери репозиторий.
3. Framework Preset: Other. Build Command оставь пустым, Output Directory тоже пустым (корень).
4. Deploy. Дальше каждый push в main будет обновлять сайт сам.

## Структура

| Файл | Что внутри |
|---|---|
| `src/config.js` | Все числа баланса: скорость, урон, фокус, физика клинка |

| `src/render.js` | Вся графика на Canvas 2D |
| `src/audio.js` | Звук, синтезированный в WebAudio |
| `src/effects.js` | Искры, дым, волны, всплывающие надписи |
| `src/main.js` | Меню и связка всего вместе |

## Как устроена боёвка

Клинок вращается вокруг плеча и тянется к углу прицела через ПД-регулятор с ограничением ускорения, поэтому у него есть инерция: удар нужно разогнать. Симуляция идёт с шагом 1/120 секунды, клинки проверяются ещё в три подшага, чтобы не проскакивали друг сквозь друга.

Когда клинки пересекаются, сравнивается скорость каждого в точке контакта:

- оба почти неподвижны: сцепка, клинки давят друг на друга;
- один быстрый, второй стоит: блок, защитник платит фокусом, при нуле фокуса блок пробит;
- второй движется навстречу, но медленнее: парирование, атакующий оглушён;
- оба быстрые и навстречу: размен, оба отлетают.

Когда клинок касается тела, урон считается по относительной скорости точки лезвия. Голова получает ×1.5, ноги ×0.7, ярость ×1.3.

## План на онлайн 1 на 1

Архитектура уже готова к этому: боец принимает абстрактный input, а не читает клавиатуру сам. Для сети достаточно добавить `NetworkController`, который отдаёт input второго игрока.

Важно: серверные функции Vercel не держат постоянные WebSocket-соединения, поэтому для онлайна нужен один из вариантов:

- WebRTC напрямую между игроками (например, через PeerJS), Vercel только раздаёт сайт;
- отдельный realtime-сервис вроде PartyKit, Supabase Realtime или Ably.

Фиксированный шаг симуляции позволяет потом сделать rollback-неткод, как в файтингах.
